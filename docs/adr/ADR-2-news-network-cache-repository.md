# ADR-2: Сетевой слой и кэш новостей

## Статус

Accepted

## Контекст

Раздел "Новости" подтягивает Top Stories из NYTimes API. Нужно было:

- сделать запросы тестируемыми (без обращения к настоящему API в тестах);
- не показывать пустой экран при холодном старте, если есть свежие данные;
- не блокировать UI на время сетевого запроса;
- кешировать картинки, чтобы скролл не дёргался каждый раз.

При этом UI у новостей довольно простой (список статей), поэтому делать здесь полноценную Clean Architecture с UseCase было бы избыточно. Решение должно быть прагматичным.

## Решение

**Сетевой клиент.** `APIClient` — тонкая обёртка над `URLSession`. Принимает `Endpoint` (протокол: host, path, method, queryItems, headers, body), сам собирает `URLRequest`, проверяет статус-код, отдаёт `Result<T, APIClientError>` через completion. `URLSession` инжектится в init — это даёт нам возможность подменить его на `URLSession` с кастомным `URLProtocol` в тестах и проверять реальный построенный `URLRequest`.

`APIClientError` отдельно содержит понятные локализованные сообщения для разных классов ошибок (нет интернета, 401, 429, decoding и т.д.), которые потом показываются пользователю.

**Кеш статей.** `NewsCacheService` пишет JSON в файл `news_cache.json` в `cachesDirectory`. У него два TTL: soft (2 минуты) — данные ещё валидны, но пора обновить, hard (24 часа) — кеш удаляется. `loadValidCache()` возвращает `NewsCacheSnapshot` с флагом `isSoftTTLExpired`, чтобы VM знал, надо ли тихо догружать. Директория файла инжектится через init (`cacheDirectoryURL`), чтобы тесты писали во временную папку и не задевали реальный кеш приложения.

**Кеш картинок.** `ImageCacheService` — двухуровневый. В памяти держит `NSCache<NSURL, UIImage>`. На диск пишет оригинальные `Data` в отдельную директорию `NewsImages`, имя файла — SHA256 от URL. Запись/чтение с диска идут через свой `DispatchQueue` (`qos: .utility`). Раз в жизненный цикл сервиса прогоняется чистка файлов старше 7 дней. Директория тоже инжектится — для тестов.

**Загрузчик картинок.** `ImageLoader` сначала смотрит память, потом диск, потом идёт в сеть через `URLSession`. Возвращает `ImageLoadTask` (по сути — отменяемая операция), чтобы ячейки таблицы могли отменять загрузку при переиспользовании.

**Репозиторий.** `NewsRepository` реализует `NewsRepositoryProtocol`: `getCachedTopStories()`, `refreshTopStories(completion:)`, `sendAnalyticsEvent()`. Внутри использует `APIClient`, `NewsCacheService`, маппинг через `NYTimesMapper` (отдельный enum со статическими функциями — без состояния, легко тестируется отдельно).

**ViewModel.** `NewsViewModel` имеет состояние `State` (`.idle / .loading / .loaded / .empty / .error`). При `viewDidLoad`:
1. Сначала отдаёт UI кэшированные статьи, если они есть.
2. Параллельно фоном делает `refreshTopStories`. Если сеть упала — оставляет показанный кеш, не переключает в `.error`.
3. Раз в 2 минуты тихо обновляет данные через `Timer`.

Все колбэки `state.didSet` диспатчит на main — UI получает обновления только на главном потоке. Сами сетевые/дисковые операции уходят на фоновые очереди `URLSession`/файлового кэша.

## Последствия

**Плюсы.**
- UI не блокируется: всё сетевое и дисковое — на фоновых очередях, обновление состояния — на main.
- Тесты прогоняются без реальной сети: `APIClient` через `MockURLProtocol`, `NewsCacheService`/`ImageCacheService` через временные директории, `NewsViewModel` через стаб репозитория. API key не требуется.
- Пользователь почти никогда не видит пустой экран — пока обновляется свежее, показывается старое.
- Двухуровневый кеш картинок убирает мерцание при скролле.

**Минусы и ограничения.**
- `NewsRepository` сейчас совмещает несколько ответственностей: вызов API, работу с кешем статей, отправку аналитики (`/posts` placeholder), резолв API key из `Info.plist`, логирование. Это нарушает SRP. Сделано так из соображений простоты — отдельная фича маленькая, и дробить её на `NewsAPIService` + `NewsAnalyticsService` + `NewsKeyProvider` сейчас выглядит избыточно. В будущем это правильный кандидат на разделение.
- TTL'ы и интервал авто-рефреша — захардкоженные константы внутри сервисов. Не вынесены в конфиг.
- `ImageCacheService.shared` и `NewsRepository` создаются по дефолту в инициализаторах — для прод-кода удобно, но настоящего DI-контейнера нет.
- Картинки не кешируются с учётом размера экрана/устройства — мы храним то, что прилетело с API.

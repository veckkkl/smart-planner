# ADR-3: Home Dashboard как отдельная фича

## Статус

Accepted

## Контекст

В требованиях финального проекта была необходимость показать как минимум одну дополнительную крупную фичу — не очередной CRUD-экран и не настройки. Хотелось чтобы Home-экран реально помогал пользователю, а не просто говорил "TBD". При этом фича не должна была требовать новых источников данных — только агрегировать то, что уже есть в репозитории задач.

Дополнительно — экран нужно было держать визуально похожим на нативные iOS-приложения (Reminders, Fitness, Calendar), потому что весь проект идёт в этой стилистике.

## Решение

Dashboard собран из четырёх блоков: статистика, календарь, список ближайших задач, empty state. Вся бизнес-логика вынесена в отдельный доменный сервис, UI только рендерит то что прислал ViewModel.

**Доменный слой.**
- `DashboardPeriod` — enum (`.week / .month / .allTime`).
- `DashboardStatistics` — иммутабельная модель с полями `total / completed / active / overdue / withoutDate` + `byPriority`. Эти 4 счётчика взаимоисключающие, их сумма даёт `total` — это позволяет рисовать donut-диаграмму без перекрытий.
- `DashboardStatisticsService` (за протоколом `DashboardStatisticsServicing`) — чистая структура, считает статистику над `[Task]` за выбранный период. Отдельные методы:
  - `statistics(for:period:)` — фильтрует задачи по периоду (по `deadline` если есть, иначе по `createdAt`), классифицирует на completed/active/overdue/без даты.
  - `upcoming(from:limit:)` — отдаёт ближайшие не выполненные задачи, отсортированные по deadline.
  - `tasksByDay(_:)` и `tasks(on:from:)` — для подсветки календаря.
- `Calendar` и `now: () -> Date` инжектятся, поэтому всё тестируется детерминированно (фиксированная дата в тестах).

**Presentation.**
- `DashboardViewModel` подписывается на `TaskRepositoryProtocol` (тот же, что использует экран задач), при каждом изменении задач пересчитывает статистику, upcoming-срез и `tasksByDay`. Состояние выбранного периода тоже живёт в VM.
- `HomeViewController` композирует блоки. Каждый блок — отдельная переиспользуемая View: `StatisticsCardView` (с donut + легенда + меню периода), `TasksCalendarView` (обёртка над `UICalendarView` с custom decoration provider), `UpcomingTasksSectionView`, `EmptyDashboardView`.
- `StatisticsDonutChartView` рисует сегменты через `CAShapeLayer` с анимацией перехода (без сторонних библиотек).
- Цвета донат и точек календаря собраны в `DashboardPalette` — softened-варианты системных синего/зелёного/красного/серого, чтобы выглядело как Reminders, а не как корпоративный дашборд.

**Календарь и переход на задачи дня.**
В `TasksCalendarView` мы предоставляем `UICalendarViewDelegate.decorationFor:` — для каждого дня спрашиваем у VM `marker(for:)` и возвращаем `Decoration.customView` с маленькими цветными точками (синяя — есть выполненные, зелёная — активные, красная — просроченные). При тапе по дню `HomeViewController` пушит `DayTasksViewController`, который работает на своём `DayTasksViewModel` (он тоже подписан на репозиторий и переотрисовывает данные при изменении). Это даёт реальное взаимодействие "дашборд → детальный экран".

## Последствия

**Плюсы.**
- Полноценная отдельная фича сверх обычного CRUD: круговая диаграмма, нативный календарь, упорядоченный список ближайших, переход к деталям выбранного дня, пустое состояние с CTA-кнопкой.
- Вся аналитика и группировка тестируются юнит-тестами (`DashboardStatisticsServiceTests`) с детерминированной датой.
- Нет дублирования данных: задачи одни и те же, и на Home, и на экране задач. Изменение чекбокса на дашборде/в детальном дне моментально отражается на других экранах через тот же observer-механизм репозитория.
- Соответствует требованиям финального проекта: дополнительная значимая фича, отдельный доменный сервис, ViewModel с покрытием, UI близкий к нативному iOS (UICalendarView, SF Symbols, Dynamic Type, Dark Mode, VoiceOver).

**Минусы и ограничения.**
- Donut рисуется вручную. Это нормально для статичных данных, но без UnitOfWork — для интерактивных подсегментов или анимаций "по клику на сегмент" пришлось бы переделывать.
- "Период" сейчас считается строго от `now()`. Произвольный диапазон (с пикером дат) не поддерживается.
- Decoration в `UICalendarView` приходится перерисовывать вручную (`reloadDecorations`), потому что Apple не пересоздаёт их при изменении данных модели. Это работает, но требует следить за тем, чтобы VM звал перерисовку.
- Все вычисления идут синхронно в main потоке. На текущем объёме задач это незаметно, на десятках тысяч записей пришлось бы выносить в фон.
